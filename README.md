# 个人视频创作指南（personal-video-creator）

把一个想法、角色或产品素材、音频、脚本或一条参考视频，做成可以直接投喂文生视频模型的完整中文提示词。

写稿用一套流程：定观看机制 → 选结构 → 排镜头与声音 → 自检。题材不对口时借外部成熟结构，动作片按密度与幅度量化，成片不行就量化回查稿子，而不是靠形容词加力。

## 能做什么

- **从一句话到方案**：先发散出几个机制不同的候选并择优，再展开构图、调度、表演与节奏。
- **按类型写稿**：18 类内容（生活情景、剧情、喜剧、萌宠、Vlog、广告、UGC、时装、MV 与舞蹈、动作、运动、车辆、奇幻、悬疑、美食、制作改造、游戏、界面动效），各有一份可增删改写的模板。
- **借用成熟结构**：27 种外部结构模板的分块、指导与陷阱，按题材分册；66 条外部提示词全文可当写作锚点，不当场发明结构。
- **动作与对抗片量化**：动作密度（单元/秒）、幅度指标（放倒、多人同时在场、抓握、低机位）、受力语法、机位黑名单与冲击预算，配两个可跑的成片实测脚本。
- **参考视频逆向**：核实时间轴与镜头，反推成一条可整段复制的完整提示词，支持换人复用与参考图准备。
- **避开已知坑**：十余条成片的失败模式整理成「现象 → 根因 → 改法」，写稿前扫一遍。
- **交付前校验**：`scripts/lint-prompt.py` 查模板残留、时间戳、素材标签、字幕与字段标题、负向约束位置与**约束冲突**、平台硬上限这类机械项；判断类的交给自检清单与看片。
- **成片复盘**：区分"用户认可""直接观察""待确认"，按镜头记录问题并回到方法层修正。

## 安装

**仓库根目录就是技能目录**，`SKILL.md` 在根上——一键安装器只读根目录 `SKILL.md` 的那种也能直接识别。

1. 把整个仓库放进客户端的技能目录，目录名保持 `personal-video-creator`
   （`git clone <仓库地址> ~/.claude/skills/personal-video-creator`，或解压后直接放进去，不用改名）。
2. 最终路径应形如 `<技能目录>/personal-video-creator/SKILL.md`。
3. 重启客户端或刷新技能列表，确认技能名出现。

若安装器要求"仓库根即技能根"（不少市场和一键安装脚本是这么做的），本仓库已经满足，无需再套一层目录。

常见客户端的默认技能目录（以你自己的客户端文档为准）：

| 客户端 | 默认位置 |
| --- | --- |
| Claude Code 及多数 Claude Agent 环境 | `~/.claude/skills/` |
| WorkBuddy | `~/.workbuddy/skills/` |
| Codex 类环境 | `~/.codex/skills/`（设置了 `CODEX_HOME` 时用其 `skills` 子目录） |

`archive/` 是个人材料，不属于技能内容，安装时可以不拷；技能只依赖根目录 `SKILL.md` 与
`references/`、`assets/`、`scripts/`。

## 使用

直接用自然语言描述任务即可，例如：

> 按这两张角色图写一条十秒的生活情景喜剧。两个人在家抢遥控器，反转要自然，表情写细，输出完整提示词。

> 反推这个视频，换成我提供的人物，只上传参考图，给我一条完整提示词。

> 按这张香水图写一条十二秒的产品广告，突出瓶身和喷雾质感，纯产品展示。

> 我还没有角色图，想做一条轻松的互动舞。先推荐造型与半身／七分身／全身取景，再给参考图提示词和编舞方向。

> 这条打斗成片被说"像减速、站在原地等时间"，帮我量一下再改稿。

也可以要求"给几个机制不同的创意""按这套方法改我的稿子""复盘这条成片并更新方法"。

## 边界

- 不自动消费生成额度、不上传发布、不修改其他技能；只在用户明确要求时使用生图能力。
- 平台规格按实际入口核对，冲突时以入口为准；未被核对的规格标注证据等级，不写成平台事实。
- 外部提示词原文、题材与证据标注可收录（作者与许可见 `THIRD-PARTY-NOTICES.md`）；样片视频、账号、原文件名与外部网址不收录。
- 收录不等于验证：外部样片的成功是原作者的声称或来源标注，个人成片的效果按反馈流程另行记录。

## 维护

- 方法按"共用 → 类型 → 题材"分层，入口保持短，按需读取；新增类型以真实请求与具体案例为依据。
- 新增或扩展外部方法时，同次更新对应分册与 `THIRD-PARTY-NOTICES.md` 的来源行，注明已读范围、采用方法与验证状态。
- 脚本改动后先跑 `python scripts/test_scripts.py`（离线，无需 ffmpeg）；装了 ffmpeg 后跑
  `motion-audit.py --selftest` / `fight-metrics.py --selftest` 做端到端验证，`lint-prompt.py --selftest` 随时可跑。
- `evals/evals.json` 改完加跑 `python scripts/test_scripts.py`（会校验 id、stage、期望条数）；
  方法改动后用 `evals/README.md` 里的三种方式抽查 2–3 条，别只看 lint 过没过。
- `scripts/fixtures/` 是回归样本（英文机位注释、复刻稿时长、嵌套时间线、模板残留、断档、
  中文合法字幕、字幕/台词/音乐与约束对撞、45 秒超时长、参考图 40 张）。
  改 lint 的判定规则前后都要跑一遍测试；新踩到的误报也补成 fixture，别再靠记忆防回归。
- 个人案例与偏好放在 `archive/`，不要写回技能本体；这是自用技能，不追求公开发布所需的完备性。
