# 平台口径与已核事实

本册记录 Seedance 2.5 与即梦／Dreamina 入口的**平台规格与提示词语法**，以及每条结论的证据等级。与[共用写法](video-core.md)、[外部方法参考](external-methods.md)配合；写法与结构在别处，这里只回答"平台到底怎么认"。

**证据等级标注**（沿用[反馈流程](feedback.md)的区分口径）：

- **【官方】**——官方页面或官方文档原文，本次已直接读取正文。
- **【多源一致】**——多个独立来源一致转述同一份官方指南，本次未能直接读到官方原文。
- **【二手待核】**——单一来源或来源性质不可靠，仅供试验，不作为依据。

**平台会改。**下列结论按 2026-10-12 核对，使用前若与实际入口冲突，以入口为准。

---

## 一、参考素材的上限与推荐区间

**【官方】**上限与推荐是两件事——**上限不等于目标**：

| 素材 | 上限 | 推荐稳定区间 |
| --- | --- | --- |
| 图片 | 30 张，单张不超过 4K | **1–8 个主体**最稳；9–12 勉强，稳定性下降 |
| 视频 | 10 段，每段 2–30 秒，合计 ≤30 秒 | 1–5 个主体，**每段 5–10 秒**；编辑用原片建议 <20 秒 |
| 音频 | 10 段，每段 2–30 秒，合计 ≤30 秒 | 1–5 个主体，每段 5–10 秒 |
| 分镜栅格图 | 建议 **<15 格** | 用线稿或火柴人；避免过锐、杂乱和大段文字 |
| 白模（粗模）参考 | 简单几何 | 去掉运动路径、坐标轴和镜头视锥，否则会漏进成片 |

- 视频与音频的 30 秒**分别计算**，不是合计 30 秒。
- 图片上限 30 中含首帧、尾帧与参考图；首帧或尾帧用参数指定时**会锁死输出画幅比例**。
- 素材超预算时按这个顺序砍：**核心角色 → 关键产品与道具 → 场景环境 → 整体风格**。风格最先砍——多数人的直觉正好相反。
- 单个视频或音频参考 2 秒太短、30 秒会被稀释；**5–10 秒是识别与稳定的平衡点**。

这一条**否定了**此前另一个社区来源所载的"上限 9 图 / 3 视频 / 3 音频"——那是某个第三方入口的自己限制，不是平台能力。

## 二、参考素材怎么指代

**【官方】**素材标签按**你实际界面的语言**写：

| 界面语言 | 写法 |
| --- | --- |
| 英文 | `@Image1`、`@Video1`、`@Audio1` |
| 中文 | `@图片1`、`@视频1`、`@音频1` |

- 官方英文页通篇写 `@Image1`（**紧贴编号，中间不加空格**）；中文官方译本写 `@图片1`。两种都对，取决于入口。
- 此前社区来源给的 `@1`／`@2` **没有依据**，不要用。
- **不要只依赖参考图里写的名字**（例如在图上标"张三"然后在提示词里直接喊张三）——官方把它列为典型失败：多人场景会混淆或重复角色。
- **不要写"图1到图4分别是四个角色"这种 respectively 句式。**官方点名的失败示例就是它——必须**一个素材一行，逐条写清归属**，即使啰嗦。
- 每个素材要回答两件事：**属于谁、具体借用什么**。只借用一部分时，**必须同时写明不继承什么**。

多视角图的正确写法（**【多源一致】**，官方指南原文形态）：

```
@图片1 定义同一盏折叠台灯的正面外观。
@图片2 定义同一盏折叠台灯的左侧结构。
@图片3 定义同一盏折叠台灯的右侧结构。
@图片4 定义同一盏折叠台灯的背面结构。
四张图片共同定义同一盏折叠台灯，成片中始终只有一盏折叠台灯。
```

**多张图是同一主体时，必须显式声明，并写死成片中的数量。**否则模型不会自己推断，会把四张视角当成四个对象。

这一条**强化**了本指南既有的"角色三视图属于同一身份"——但原来只说了身份相同，**没要求写死数量**。以后用到多视角素材，把"成片中只有一个人／一盏灯"这类**数量句**一并写上。

> 【二手待核】另有来源称官方建议**不要提供角色三视图**，理由是正面／侧面／背面会被当成三个人，建议只用一张正面大头照；同时又说另一套做法是"脸特写＋无头的上半身＋背面"三张分开。两者互相矛盾，且都与上面那条官方原句（多视角可写、但必须显式声明）不冲突——**先用显式声明加数量句，三视图是否更差留待自己实测。**

## 三、负向约束怎么写

**【官方】**负向约束**存在，但没有独立通道**。它是写在提示词里的自然语言约束，官方模板的结尾就是这个位置：

```
Preserve [身份、服装、标志、物体几何]
Avoid [不需要的剪切、镜头行为、伪影、多余物体、文字]
```

官方对写法的要求很明确：

> 负面指令在**保护某个具体的制作要求**时最有效。**要短、要具体、成组放在结尾。不要写一大串泛泛的黑名单——那会和场景描述抢注意力。**

- 官方文档中**明确列出支持负向控制**的项目是：字幕、背景音乐、音频。"不要字幕。""不要 BGM，只保留环境声和动作音效。""不要任何声音。"
- 官方模板里 `Preserve`（必须不变）与 `Avoid`（禁止出现）是**分开两块**，不要混在一起写。
- **正向描述优先**：只有素材职责、编辑范围和容易误带入的内容才需要明确限制（**【多源一致】**）。
- 反面做法：写"禁止变形"不如写"人物面部保持正常结构比例"；泛泛的"电影感、专业、高质量、杰作"在 2.5 上基本无效输入（**【二手待核】**）。

**本指南现在"约束块放结尾、只写与本片有效的禁止项"的做法与官方一致，不用改。**

## 四、时间戳

**【官方】**

- **以 1 秒为基本单位**。不要写成"第 10.5 秒"，写成"第 10 秒到第 14 秒"。
- 时间轴**必须连续、不能有缺口**。`0-3s… 5-6s…` 这种断档是错的；`0-3 秒… 3-7 秒… 7-15 秒` 才对。
- **不要把时间戳用于高频动作**，官方例子就是"每秒摇头三次"——这种控不住的。
- 三种控制方式都支持：清晰时间区间、时间点控制（"在第 2 秒，一道金色闪电从画面上方落下"）、相对时间控制（"男主按下快门后画面定格 1 秒"）。
- 一个时间段里的内容**太少，模型会自行加戏；太多，会被截断或切得很碎**。密度要配得上时长。

**这一条确认了时间戳分段是官方能力**，此前社区两个来源关于它的分歧可以结案。**同时它也说明：每秒动作数不能靠时间戳去压——那是排练逻辑，不是平台控制项。**

## 五、声音、台词与字幕的分隔符

**【多源一致】**（五种独立来源一致转述官方指南，含一份官方指南的完整中文译本；本次未在官方英文页正文中直接读到）：

同一个镜头里有多层声音或文字、需要区分时，用四种符号：

| 内容 | 符号 | 示例 |
| --- | --- | --- |
| 音乐 | `( )` | `(背景播放舒缓节奏的钢琴乐)` |
| 音效 | 尖括号 | 示例在转述中均被网页转义吃掉，**具体字形待自己核对** |
| 台词 | `{ }` | `{你好，欢迎回来}` |
| 画面字幕 | `【 】` | `【第一章：启程】` |

- 符号不是必需的：**普通句子仍然可以用**。只有当一句话有两种读法、或需要区分层次时才加（**【二手待核】**）。
- **台词必须用同一种语言**，同一提示词里混用两种语言会出问题；非中英台词要在台词**前面**声明语言。
- 推荐公式：`台词语言 + 地区变体或口音 + 表达方式 + 说话人 + {台词内容}`
  例：`台词语言：美式英语。女孩用自然、口语化的美式英语说：{I thought you weren't coming.}`
- 优先支持的语言：中文、英语、西班牙语、印尼语、马来语；另覆盖泰语、阿拉伯语、葡萄牙语、越南语、日语、韩语。

### 需要留意的一处冲突

本指南与外部模板规则里的【】一直用于**字段标题**（`【人物锁定】`、`【分镜】`、`【镜头01】`），而官方语法里 **`【 】` 表示画面字幕**。

- 这**可能**让字段标题被当成字幕渲染。已有的成功案例（樱花庭院、玄幻剑尊）用的都是【】标题且用户表示效果通过，所以**未必造成实际损害**，也**可能**正是此前成片里字幕乱入、字数出错的来源之一。
- **不要为此整体推翻现有格式。**建议做一次对照：同一故事写两版，一版保持【】标题，一版把字段标题换成不带括号的写法（如 `人物锁定：` 或 `▍人物锁定`），只改标题、其余不动，各生成一次比对。结果出来再决定是否换。这条待你自己实测，本指南不代为下结论。

## 六、提示词结构与顺序

**【官方】**官方给的是**结构和顺序**，不是字数。

官方八段式，顺序固定（"把不可妥协的事实放在前面，动作与时间居中，声音和约束收尾"）：

`格式 → 主体 → 动作 → 环境与场景 → 镜头 → 画面风格 → 时间 → 音频与约束`

对应内容：

| 段 | 写什么 | 例 |
| --- | --- | --- |
| 格式 | 时长、画幅、镜头结构 | `30 秒，16:9，四个相连镜头` |
| 主体 | 身份、服装、产品或核心对象 | `同一位女性，来自 @Image1，穿红色外套` |
| 动作 | 有明确起止的可见动作 | `她打开盒子，取出腕表，扣上表带` |
| 环境 | 地点、时间、天气、实景细节 | `蓝调时刻的楼顶，湿混凝土，城市倒影` |
| 镜头 | 景别、镜头感、运动、焦点行为 | `中近景，缓慢顺时针环绕，浅景深` |
| 画面风格 | 光照、色调、质感、写实级别 | `柔和轮廓光，冷阴影，高端商业写实` |
| 时间 | 逐拍推进与转场 | `00–06s 铺垫；06–18s 演示；18–26s 兑现；26–30s 主画面` |
| 音频与约束 | 对白、环境声、音效，以及必须不变的东西 | `柔和城市环境声；保持标志与面部一致；无多余文字或跳切` |

官方指南另有对应的四段式（**【多源一致】**）：`素材指代 + 一句话概述 + 时间线或镜头顺序 + 全局约束`。

### 关于长度：官方没有给字数

**【官方】**官方指南**没有任何字数或词数建议**。它给的是：

> 基础提示词不需要堆一堆形容词。重要的是让动作、镜头和声音构成一个完整的八秒弧。

> **先描述主动作，把详细的措辞留给少数几个记忆点。**

第二句是本指南"细节不要平均分配"的官方旁证——**官方自己就是这么要求的**。

因此：此前社区来源给出的"最优 342 词"与"30–100 词"**都没有官方依据，两者都不可采信**。判断标准不是字数，而是**关键画面是否可执行、结构是否按上面的顺序组织**。

其他官方写法纪律（**【官方】**）：

- **写可观察的指令**："她转向窗户并停顿"能给模型可执行的内容；"让它充满情绪和美感"不能。
- **关键指令说一次就够**，放在靠前位置，并在相关的时间段就地再落实一次，**不要到处重复**。
- **不要把剧本直接粘贴进提示词**，冗余文字会扰乱模型（**【多源一致】**）。
- **一个镜头一个主运镜**；"一边平移环绕一边推进"这类组合会让画面崩掉，确需两种就拆成两个镜头（**【多源一致】**，与本指南[机位可行性](camera-feasibility.md)的"一拍一个主运镜"一致）。
- **不要试图固定 seed**，对 Seedance 2.0 系列无效；一致性靠参考图和主体定义实现（**【多源一致】**）。

## 七、时长、分辨率与入口

**【官方】**

- 单次基础生成 **4–30 秒**；Long Video 模式 **30–180 秒**；Extend 可在 30 秒以内的原片上追加 4–30 秒，多轮累计至多约 60 秒。
- 输出分辨率：官方用户指南列出的是 **480p 与 720p**。**输入可以是 4K，输出不等于 4K**，不要把两者混为一谈；某个入口支持 1080p 不代表所有入口都支持。
- 30 秒素材本身**不意味着**必须切到长视频模式。
- 视频编辑：原片 20 秒以内更稳。

**【二手待核】**9:16 竖屏生成时出现不需要字幕的概率更高，16:9 生成后再裁更稳——未核实，可自行对照。

## 八、此前挂着的问题：结论

| 问题 | 结论 |
| --- | --- |
| ① 锚点真实语法 | **成立**。按界面语言用 `@Image1`／`@Video1`／`@Audio1` 或 `@图片1`／`@视频1`／`@音频1`。社区来源的 `@1`／`@2` 无依据。多视角素材必须显式声明为同一主体并写死数量。 |
| ② 是否支持负向提示词 | **支持，但不是独立通道**。是写在提示词末尾的自然语言约束块（`Preserve` ＋ `Avoid`），要短、要具体、成组放结尾；官方明确列出的负向项是字幕、BGM、音频。现有做法正确，无需改。 |
| ③ 实际最优长度区间 | **不存在这个区间。**官方从未给字数建议，只给结构与顺序，并要求"详细措辞留给少数记忆点"。两个社区来源的数字都不可采信。 |

## 九、写稿时的落地检查

1. 素材标签与**实际界面语言**一致，编号与上传顺序一致，**没有素材就不写标签**。
2. 多视角素材已显式声明为同一主体，并写死了成片数量。
3. 素材数量在推荐区间内（图 1–8，视频音频各 1–5 段、每段 5–10 秒）；超了就按"角色 → 道具 → 场景 → 风格"的顺序砍。
4. 每个素材都写了"借用什么"和"不继承什么"，且**没有用"分别是……"的句式**。
5. 时间戳连续、无缺口，结束时间等于总时长，以整秒为单位，**没有用于高频动作**。
6. 约束块在结尾、短而具体，`保持/禁止` 分开写；正向描述优先。
7. 提示词按"格式 → 主体 → 动作 → 环境 → 镜头 → 风格 → 时间 → 音频与约束"的顺序组织，**关键约束只说一次并在相关时间段就地落实**。
8. 台词语言已声明，同一提示词内语言统一。
9. 没有把剧本原文粘进提示词；一镜一个主运镜。
10. 若用了【】做字段标题，知道它与"画面字幕"同符号——需要区分声音或文字层次时优先改标题写法，并做一次对照。
