# 个人视频创作指南

把生活片段写成可用于生成视频的情景提示词，重点是角色一致、具体表演、可信的动作与声音，以及适合故事的节奏。当前成熟模块为生活情景短片；后续按实际创作需求扩展。

## 入口与按需阅读

每次先读 [个人偏好](references/preferences.md)，本次用户要求优先。

| 当前任务 | 读取资料 | 交付 |
| --- | --- | --- |
| 想情景、找不同创意 | [生活情景方法](references/life-scenes.md)中的创意部分 | 有差异的情景、关键反应与结尾；用户只要创意时不强行展开全文 |
| 写完整提示词、改已有提示词 | [生活情景方法](references/life-scenes.md)及[七模块模板](assets/life-scene-prompt-template.txt) | 可以直接复制的完整提示词；仅改局部时按用户范围交付 |
| 参考以前满意的效果 | [案例索引](references/case-index.md)，再读相关案例 | 借用有效的表演与叙事方法，另写当前故事 |
| 借鉴外部已验证提示词 | [完整提示词案例研读](references/external-cases.md)，按题材选择案例 | 学习具体表演、信息揭晓和动作组织，保留来源与原案例条件 |
| 看成片、学习反馈、更新指南 | [反馈与维护](references/feedback.md)及相关案例 | 有依据的评价、必要修改，以及用户已授权范围内的记录更新 |

遇到多类参考素材混用、喜剧笑点安排或逐镜修复时，按需读[外部方法参考](references/external-methods.md)。其中保留来源和适用条件，常规创作不需要联网读取整套外部仓库。

## 创作流程

1. 从用户材料确定核心事件、角色、情绪变化和结尾。优先复用已提供的信息；缺少非关键项时采用个人偏好，角色参考缺失时不虚构已经绑定。
2. 先安排人物看见或听见什么、怎样回应，再安排对白、镜头与时间。短喜剧看误会如何成立，含蓄情感戏看没有说出口的话如何被观众看懂。
3. 把参考图映射到具体角色。三视图、面部特写和多角度可以属于同一身份，不能在视频里变成多个人；服装、场景与表情按当前剧情分别控制。动物和非人角色绑定对应外观特征。
4. 完整提示词采用【角色绑定】【服装】【视角与摄影】【场景】【声音】【镜头】【执行要求】。模板是填写依据，交付前删除占位符、无关可选项和写给创作者的操作说明。
5. 核对总时长、对白容量、反应留白、动作起止、视角归属和跨镜连续性。关键表情必须在画面里能看见；抽象情绪不能只停留在总纲。
6. 直接交付所需提示词。用户明确满意并提供实际使用的最终稿时，再按反馈流程归档；不能把未生成的方案写成验证成功。

## 创作与维护边界

- 时长、镜头数量、第一或第三人称、表演强度、音乐与结尾方式服务当前故事，不固定套用某个旧案例。
- 支持角色参考与文字创作；不要把写提示词扩展为自动消费生成额度、上传发布或修改其他技能。
- 《明天》的长停顿、《狗打的》的十秒节奏、换装案例的羞恼反击均有特定用途，不作为所有短片的默认剧情。
- 更新时区分个人偏好、单个案例经验和成片已观察事实。保留实际最终提示词，并记录证据来自用户反馈还是直接看片。
- 外部已有验证的案例可直接作为创作参考，保留来源和验证状态；新故事的迁移结果按成片反馈积累。外部案例和方法不标成个人实际生成成功。
- 新类别有实际请求和可复用方法后，再增加对应资料及入口。现有七模块可以保留，但允许按新类别的需要扩展；不要预建空模块。
