# 个人视频创作指南

把主题与素材写成可用于生成视频的提示词。生活情景只是其中一种类型；其他类型依据已读外部案例形成分类模板。重点是主体连续、具体动作与表演、符合类型的摄影与声音，以及适合目标的节奏。

## 入口与按需阅读

每次先读 [个人偏好](references/preferences.md)，本次用户要求优先。

| 当前任务 | 读取资料 | 交付 |
| --- | --- | --- |
| 想创意、选类型 | [类型与模板索引](references/video-types.md)；生活情景再读[生活情景方法](references/life-scenes.md) | 有区别的目标、关键变化与结尾；只要创意时不强行展开全文 |
| 写完整提示词、改已有提示词 | [共用写法](references/video-core.md)、索引中对应的一个内容模板；按需要读画风或制作方法 | 可以直接复制的完整提示词；修改范围与当前类型相符 |
| 参考以前满意的效果 | [案例索引](references/case-index.md)，再读相关案例 | 借用有效的表演与叙事方法，另写当前故事 |
| 借鉴外部已验证提示词 | [类型索引与代表案例](references/video-types.md)；生活情景按需读[完整提示词案例研读](references/external-cases.md) | 学习当前类型的表演、摄影、动作与状态组织，保留来源与原案例条件 |
| 看成片、学习反馈、更新指南 | [反馈与维护](references/feedback.md)及相关案例 | 有依据的评价、必要修改，以及用户已授权范围内的记录更新 |

遇到多类参考素材混用、喜剧笑点安排或逐镜修复时，按需读[外部方法参考](references/external-methods.md)。其中保留来源和适用条件，常规创作不需要联网读取整套外部仓库。

## 创作流程

1. 从用户材料确定主要目标、主体、变化和结尾，选最合适的内容类型。优先复用已提供的信息；缺少非关键项时按本片需要选择，缺失的素材不虚构已经绑定。
2. 按类型安排可见结果：剧情与喜剧看触发和回应，广告与时装看主体展示，MV 看音频和表演，动作看接触与后果，过程或界面看片中状态怎样推进。
3. 分配人物、动物、产品、场景、音频或分镜素材的职责，固定身份与结构，明确允许变化。三视图与分镜页排版不直接成为成片构图。
4. 根据内容目标、素材和实际生成入口选择最合适的结构。对应模板是起点，可改名、增删、合并或重排字段；需要时也可用连续描述、时间线或平台明确要求的格式。生活情景的七模块是一种可选写法。画风和制作方法放到本片合适的位置，删除空栏目、占位符与创作者说明。
5. 按类型检查时长、动作容量、声音依据、信息可见范围和跨镜状态。细小表情要可读，产品结构、关键接触、过程变化与 UI 反馈也要具体可见。
6. 直接交付所需提示词。用户明确满意并提供实际使用的最终稿时，再按反馈流程归档；不能把未生成的方案写成验证成功。

## 创作与维护边界

- 时长、画幅、画风、镜头数量、视角、表演强度、音乐与结尾服务当前目标，不固定套用某个旧案例。
- 支持角色参考与文字创作；不要把写提示词扩展为自动消费生成额度、上传发布或修改其他技能。
- 《明天》的长停顿、《狗打的》的十秒节奏、换装案例的羞恼反击均有特定用途，不作为所有短片的默认剧情。
- 更新时区分个人偏好、单个案例经验和成片已观察事实。保留实际最终提示词，并记录证据来自用户反馈还是直接看片。
- 外部已有验证的案例可直接作为创作参考，保留来源和验证状态；新故事的迁移结果按成片反馈积累。外部案例和方法不标成个人实际生成成功。
- 按本次类型读取对应模板，避免每次加载全部模板。新增类型仍以实际用途和具体案例为依据；用户要求的结构与范围优先。
